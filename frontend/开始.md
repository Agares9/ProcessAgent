  ## 四、前端设计原则

  这是一个企业决策工作台，不是营销落地页。

  设计应保持：

  - 专业
  - 安静
  - 信息清晰
  - 适合企业管理者连续使用
  - 信息密度适中
  - 支持桌面端和移动端
  - 页面区域圆角不超过 8px
  - 不使用大面积渐变
  - 不使用装饰性发光球
  - 不做大幅 Hero 营销页面
  - 不把页面各部分都设计成悬浮卡片
  - 不嵌套卡片
  - 不让标题字号过大
  - 不使用随屏幕宽度变化的字体尺寸

  继续使用 `lucide-react` 图标，不要手绘 SVG。

  ## 五、目标交互流程

  前端最终应该支持：

  用户输入问题
  → 后端识别行业和意图
  → 显示任务复杂度
  → 显示 Agent/Skill 执行阶段
  → 显示百分比进度
  → 接收最终自然语言回答
  → 展示证据来源和计算依据
  → 用户继续补充信息
  → 多轮上下文持续合并

  不要显示不准确的预计剩余时间。

  运行状态建议使用：

  正在理解业务问题                  15%
  正在检索行业资料                  35%
  正在分析数据和约束                60%
  正在校验证据和计算结果            82%
  正在组织最终方案                  95%

  超过15秒后可以显示：

  多个分析任务正在协同处理，复杂问题需要一些时间。

  不要显示：

  - Loading weights
  - HuggingFace 下载日志
  - Transformers 进度条
  - Python 内部日志
  - Agent 内部推理过程

  ## 七、输入和会话要求

  输入框需要支持：

  - 多行输入
  - Enter 发送
  - Shift+Enter 换行
  - 发送
  - 停止生成
  - 清空输入
  - 新建会话

  按钮必须明确区分：

  - `清空输入`：只清空输入栏
  - `新建会话`：开始新的上下文
  - `删除会话`：删除历史会话

  不要使用含义不清楚的“清空”。

  新会话必须使用新的 session ID，避免历史助手回答污染新问题。

  创建消息 ID 时必须保留兼容回退，不能只使用：

  crypto.randomUUID()

  应使用带回退的方法，例如：

  function createMessageId() {
    if (
      typeof crypto !== "undefined" &&
      typeof crypto.randomUUID === "function"
    ) {
      return crypto.randomUUID();
    }

    return `msg-${Date.now().toString(36)}-${Math.random()
      .toString(16)
      .slice(2, 8)}`;
  }
